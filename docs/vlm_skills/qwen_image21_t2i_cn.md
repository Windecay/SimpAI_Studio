# Qwen Image 2.1 PE 文生图提示词技能

当 `Qwen2.1-Edit` 没有上传图片、用户要生成新图时使用这份技能。内容
来自共享的 `image-prompt-t2i` skill，并已按 SimpAI 的提示词 action 约定
整理。

## 输出边界

- 只写一段可以直接交给生成模型的提示词。
- 不输出共享 skill 的 JSON 外壳、`rewritten_prompt`、`wh_ratio` 或
  `ratio_follow` 字段。比例和分辨率由 SimpAI 预设控件管理。
- Canvas Agent 请求中，把最终提示词放入运行时 action 的 `prompt` 字段，
  外层 JSON 仍遵循运行时提供的 action 合同。
- 提示词正文不能包含 Markdown 围栏、标题、分析、模型参数、分辨率、
  seed、steps、CFG、sampler 或 LoRA 写法。

## 八步提示词结构

按共享 skill 的八步顺序在内部规划，再输出一段连贯的成品画面描述：

1. 先区分固定约束和开放内容。主体名称、数量、颜色、位置、比例、版式
   以及用户要求显示的文字必须原样保留；“清晰”“无噪点”“使用双引号”等
   生成要求只执行，不写进画面描述。
2. 确定画幅方向和比例。用户指定的比例优先；未指定时根据主体选择横向
   `3:2`、纵向 `2:3`、方形 `1:1` 或宽屏 `16:9`。比例只由预设控件表达，
   不能写入提示词正文。
3. 用一句约二十词的开场句说明媒介、风格、主体和背景或主色调，明确这是
   一张成品画面，而不是给渲染器的操作说明。
4. 在内部列出画面元素的位置和所有可读文字。位置要覆盖上方、下方、左右
   边缘、角落和中心，避免所有元素都挤在画面中间。
5. 按画面阅读顺序展开：先写背景和承载表面，再写顶部区域，随后从左到右
   写主体区域，最后写底部或前景。单一主体则按背景、姿势与位置、头部和
   面部、身体与服装、手持物和边缘细节展开。约三分之一的句子以位置短语
   开头，例如“在画面右侧”或“在左上角”。
6. 按阅读顺序逐一处理画面文字，说明位置、字重、颜色、大小和原文。文字
   必须使用英文直双引号，保留用户给出的字符、语言、大小写、标点和空格；
   不自行添加招牌、Logo、字幕、水印或翻译。
7. 单独说明光线来源、方向和软硬程度，以及产生的阴影和高光。不要让光线
   只停留在抽象的“电影感”或“高级感”。
8. 用最后一句回到整体画面，概括构图平衡、色彩、媒介风格和氛围；最后一
   句之后不要再添加总结。

复杂画面默认约二十句、四百至五百个英文词，简单画面可以缩短，但不能为
   凑长度加入用户没有要求的事实。使用现在时、第三人称和可观察的具体内容；
   给颜色加明暗或饱和度修饰，写清材质、数量、人物姿势和空间关系，保证阴影、
   反射、尺度与光源一致。不要使用“masterpiece”“8K”“highly detailed”等
   空泛质量口号，也不要把提示词写成“请生成”或“模型应该”。

## 画面文字

- 画面中需要出现的文字按字面处理。
- 用户给出文字时，保留原字符、语言、大小写、标点和空格。
- 每段实际显示的文字都用英文直双引号括起。
- 不自行增加招牌、标题、Logo、字幕、水印或翻译。

## 长度和语言

- 这个 Qwen 目标默认输出英文画面描述。画面内引号文字无论使用什么
  语言，都必须按用户要求原样保留。
- 提示词只描述已经呈现的画面，不写给用户的解释，也不写给渲染器的操作
  指令。描述不确定且用户没有固定的细节时，可以使用自然的观察性措辞，
  但固定约束必须明确。

## 返回前检查

确认提示词描述的是一个连贯画面，用户的明确约束全部保留，主体关系
可以直接看懂，引号文字准确，并且执行参数没有混入提示词正文。
