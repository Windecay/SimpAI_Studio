# Studio 独立媒体图库开发方案

更新日期：2026-08-19

状态：阶段 1、阶段 2、阶段 3 基础能力已完成，进入真实入口回归

## 1. 目标

把当前“历史记录”入口升级为 Studio 自己的媒体图库页面。页面仍由 Studio 后端提供，但不再把 `log.html` 当作数据源，也不依赖 Gradio `Gallery` 组件的选择状态、分页和媒体访问。

目标页面应具备：

- 图片、视频、音频统一浏览。
- 左侧日期栏快速定位日期。
- 中间连续瀑布流，向下滚动自动加载更早内容。
- 搜索、类型筛选、排序和收藏筛选。
- 单项详情、全屏查看、原文件下载。
- 生成参数只读展示，图库元数据可编辑。
- 多选、收藏、标签、备注、回收站、恢复和永久删除。
- 桌面端、移动端、深色主题、浅色主题和中英文界面。

## 2. 当前基础

- 生成文件已经按用户和日期目录保存：`outputs/YYYY-MM-DD`。
- `private_logger.py` 会生成 `log.html`，并在文件过大时生成归档日志。
- `enhanced/gallery.py` 已有媒体类型、内嵌元数据和预览图读取能力。
- `modules/canvas_workbench_media_gallery.py` 已有日期目录扫描和基础媒体列表接口。
- `webui.py` 已有独立 FastAPI 路由、预览路由和原文件下载路由可以参考。
- 传统 Gradio 相册继续保留，第一阶段不改变其行为。

## 3. 页面设计

### 3.1 桌面布局

```text
┌──────────────┬───────────────────────────────┬──────────────┐
│ 日期导航     │ 类型 / 搜索 / 排序 / 筛选       │ 详情面板     │
│ 2026-08-19   │                               │              │
│ 2026-08-18   │      连续瀑布流媒体区域         │              │
│ 2026-08-17   │                               │              │
└──────────────┴───────────────────────────────┴──────────────┘
```

- 顶部工具栏高度约 `52-56px`。
- 左侧日期栏宽度约 `190-220px`，独立滚动，显示日期和数量。
- 中间使用连续瀑布流，默认最新内容在上方。
- 右侧详情面板宽度约 `320-380px`，可收起。
- 日期不使用固定下拉框作为主要入口。
- 当前滚动位置跨过日期时，左侧当前日期自动更新。
- 点击日期后，定位到该日期的第一项；未加载的数据先请求再定位。

### 3.2 移动布局

- 左侧日期栏改为滑出面板。
- 详情面板改为底部抽屉。
- 顶部工具栏分为搜索行和筛选行。
- 继续保留日期快速跳转、收藏、下载和删除入口。

### 3.3 媒体卡片

- 缩略图使用固定比例或索引中的真实尺寸，减少瀑布流加载时的布局跳动。
- 图片显示原图缩略图。
- 视频显示海报、时长和视频标识。
- 音频显示封面区域、时长和播放按钮。
- 收藏和选择按钮只在悬停、聚焦或选择模式显示；触屏设备需要有固定可触达入口。
- 卡片圆角保持在现有界面允许范围内，不使用大圆角。

### 3.4 查看与详情

- 单击媒体打开详情面板。
- 全屏按钮打开查看器，支持上一项、下一项、按钮和鼠标滚轮缩放、视频控制和下载。
- 详情分为生成信息和图库信息两组。
- 生成信息只读：提示词、负面提示词、模型、尺寸、采样参数、工作流摘要。
- 图库信息可编辑：标题、标签、评分、收藏、备注。
- 长文本使用可展开区域和滚动容器，避免撑开页面。

## 4. 视觉规范

图库不引用无限画布的青绿色变量。

深色主题使用 Studio 现有灰阶和暖色强调：

- 背景：`#111318` / `#18191d`
- 面板：`#202227` / `#24262b`
- 媒体工具区：`#2b2e35`
- 边框：`#3f3f46`
- 主文字：`#d7dce3`
- 次要文字：`#aeb6c2`
- 主强调：`#f97316` / `#fb923c`
- 信息和焦点：`#63a7ff`
- 收藏：`#f0b84b`
- 删除：现有红色语义色

浅色主题使用对应的 Studio 变量，不新增单独的浅色配色体系。新页面复用现有字体、控件高度、边框、主题切换和 Font Awesome 图标。

## 5. 数据层

### 5.1 索引位置

每个用户使用独立 SQLite 文件：

```text
<user_dir>/gallery/media_library.sqlite3
<user_dir>/gallery/thumbnails/
<user_dir>/gallery/trash/
```

原媒体继续保存在 `outputs/YYYY-MM-DD`，图库索引只保存相对路径，不把绝对路径发送给浏览器。

### 5.2 媒体记录

核心字段：

- 稳定媒体 ID。
- 用户 ID和相对路径。
- 日期目录、媒体类型、MIME、文件大小、修改时间。
- 宽度、高度、时长和缩略图状态。
- 生成参数 JSON 和可搜索文本。
- 标题、标签、评分、收藏、备注。
- 回收站状态、原始路径和删除时间。

生成元数据和用户元数据分开保存。默认不改写原图片或视频。

### 5.3 索引策略

- 首次打开图库时，优先快速建立日期和文件索引。
- 元数据读取和视频探测放到后台任务；视频海报直接复用现有 Gradio 预览路由，独立图库不再生成第二套海报缓存。
- 新生成文件写入索引，后台扫描负责发现外部新增、移动和删除。
- 使用文件大小和修改时间判断是否需要重新读取。
- 旧 `log.html` 和 `log_*.html` 只作为历史元数据导入来源。
- 解析旧日志时只提取文本和结构化字段，不能把原始 HTML 直接插入新页面。

## 6. API 边界

页面入口：

```text
GET /simpleai/gallery/app?__theme=dark&__lang=cn
```

建议接口：

```text
GET   /simpleai/gallery/api/dates
GET   /simpleai/gallery/api/items
GET   /simpleai/gallery/api/items/{media_id}
PATCH /simpleai/gallery/api/items/{media_id}
POST  /simpleai/gallery/api/items/trash
POST  /simpleai/gallery/api/items/restore
DELETE /simpleai/gallery/api/trash
POST  /simpleai/gallery/api/rescan
GET   /simpleai/gallery/api/rescan/status
GET   /simpleai/gallery/media/{media_id}
GET   /simpleai/gallery/thumbnail/{media_id}
```

列表接口使用游标，不使用页码：

```json
{
  "items": [],
  "next_cursor": "...",
  "has_more": true,
  "date_summary": []
}
```

媒体接口负责 Range 请求、内联播放和下载文件名。所有接口都必须以当前用户身份解析输出目录，浏览器不能提交任意绝对路径。

## 7. 删除与恢复

- 普通删除移动到用户图库回收站，不立即销毁原文件。
- 恢复时回到原始日期目录。
- 同名文件存在时生成明确的冲突提示，不覆盖已有文件。
- 永久删除单独确认。
- 删除和恢复后刷新 SQLite、日期计数、缩略图缓存和旧 Gradio 相册缓存。

## 8. 国际化与主题

- 页面启动参数读取 `stage.__lang`、`stage.__theme`，并同步到 URL。
- 可对照翻译的 UI 文案写入 `language/cn.json` 和 `language/en.json`。
- 不在页面中拼接英文和中文。
- 日期和文件大小使用当前语言的格式化规则。
- 所有可见文字都经过统一本地化函数。

## 11. 性能要求

性能是图库功能的必要条件。页面不能因为某一天有几百或上千个媒体而失去响应。

### 11.1 数据与接口

- 页面首次加载只请求固定数量媒体，默认每批不超过 48 项。
- 列表接口只返回卡片所需的轻量字段，不在列表请求中读取完整生成元数据。
- 详情面板打开后再请求完整元数据。
- 日期数量使用 SQLite 聚合查询，不扫描和解析整份 `log.html`。
- 正常浏览使用游标分页，不能把当天或全部日期的媒体一次性返回。
- 首次索引、旧日志导入、视频探测和缩略图生成放在后台任务中。
- 普通页面请求不执行完整输出目录扫描；扫描只处理新增或修改过的文件。

### 11.2 浏览器与媒体

- 缩略图使用磁盘缓存，列表不直接读取原始大图或视频首帧。
- 图片使用 `loading="lazy"` 和异步解码，视频只加载海报，用户查看时再加载媒体流。
- 瀑布流使用 IntersectionObserver 触发加载，搜索请求需要取消过期请求。
- 页面保持有限的活动 DOM 数量，长期滚动不能无限增加媒体节点。
- 已离开视口的卡片允许回收，重新滚回时从索引数据和缩略图缓存恢复。
- 原始视频和音频支持 Range 请求，避免打开详情时读取整个文件。

### 11.3 性能预算

- 已建立索引后，日期统计和首批媒体列表在 10,000 项数据下目标为本地 p95 不超过 200ms。
- 首屏只渲染首批媒体，不因为历史日期数量增加而扩大首屏 DOM。
- 连续浏览 1,000 项媒体后，活动媒体节点目标保持在 240 项以内。
- 滚动、日期定位和打开详情不能触发整页重新渲染。
- 100 MB 以上的单个视频不能阻塞日期统计、瀑布流加载或详情面板打开。
- 所有性能预算需要使用 100、1,000、10,000 项媒体夹具和真实用户 outputs 分别验证。

### 11.4 性能回归

- 增加索引扫描、日期查询、游标分页、缩略图缓存和批量 DOM 数量测试。
- Playwright 记录首屏时间、首批媒体时间、滚动期间长任务、请求数量和活动节点数量。
- 性能测试失败时，先定位是索引、API、缩略图、媒体解码还是 DOM 增长，不用扩大批次或关闭功能来掩盖问题。
- 旧 `log.html` 只保留历史查看用途，不再作为图库正常浏览路径。
